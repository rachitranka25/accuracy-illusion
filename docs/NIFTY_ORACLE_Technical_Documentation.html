1Executive summary & the honest truth

Nifty Oracle is a self-hosted, zero-cost intraday forecasting system for two Indian index instruments — BankNifty and Nifty50. It answers one question every minute: which way is the index likely to move, how sure are we, and is now a good time to act? It never places live orders; it forecasts, paper-trades, and enforces risk discipline.

Update — 28 July 2026 (supersedes stale details below).
  • Single engine. The project was consolidated to one forecast engine, forecast_engine.py. The legacy "Beast" (VIX/cross-index) and the volatility engine were moved to experiments/; the Upstox integration was deleted (Angel One is the only live feed). See STRUCTURE.md.
  • Head-to-head verdict. New vs legacy, logged live on Angel data, had no persistent winner — legacy led in the morning and reversed by the close (BankNifty 60m went −23 → +22 in one day). Single-window numbers flip; that is noise, not edge.
  • Accuracy ≠ profit. A cost-aware A+ selective backtest (STRONG + prime window + full trend alignment, adaptive ATR stops, slippage, one entry per setup) on 28 Jul lost money on both indices — BankNifty −₹4,629 (profit factor 0.20), Nifty50 −₹3,300 (0.52). A typical 30-min move (~36 / ~14 pts) barely exceeds round-trip cost+slippage (~27 / ~10 pts), and per-minute hit-rates are inflated ~8–11× by autocorrelation. Scored as distinct trades, the edge disappears.
  • Security. Secrets live only in .env. The Angel TOTP secret is a live 2FA bypass and a .gitignore does not protect a zipped folder — if it was ever shared, rotate the API key and reset TOTP.
Update — 30 July 2026 (data breakthrough + the exhaustive investigation).
  • Real data unlocked, free. The index spot has volume=0 (its "VWAP" is fake). We now pull index futures with real volume from Angel (fetch_futures.py: ~2.5yr daily, ~3mo 5-min) and 2 years of per-strike option EOD with Open Interest from the NSE F&O bhavcopy (fetch_bhavcopy.py; free, not geo-blocked). No IV (compute from premium); intraday per-strike OI remains paid-only.
  • 100+ strategies tested (price, OI/PCR, cross-index, money-flow, regime, ensemble, volatility, VRP) — all per-day / out-of-sample with half-split stability. Nothing beats ~53-54% direction robustly. Gap-fade looked 62% but per-day = 45% (autocorrelation). PCR-extremes hit 58% and was briefly cost-positive, then decayed and died (last 6 mo: 36%, PF 0.74). Volatility prediction is the one thing that holds (~54-65% per horizon) — but it forecasts magnitude, not direction.
  • VRP is real but not retail-tradeable. Short ATM straddles win 62-72% (premium > realized move) — a classic Taleb distribution: retail option costs eat the edge and a single bad week (−₹50-70k) can erase months. The defined-risk (iron-fly) version caps the tail but costs then push net to ~breakeven/loss. VRP is the market-maker's edge (their cost ≈ 0).
  • Conclusion (theory + our data agree). A high win-rate is a warning sign of hidden tail risk, not skill; short-horizon prediction is dominated by microstructure noise; the only real micro-edge is HFT order-book / latency arbitrage (needs colocation). Chase expectancy, not accuracy. Treat this system as honest information / learning, not an income source.

Two engines, one philosophy

  • Forecast Window (forecast_engine.py) — an every-minute, multi-horizon direction forecaster (5m / 15m / 30m / 60m) built on 8 LightGBM models. Surfaces a ⭐ STRONG signal only when several horizons agree with high confidence during the model's reliable hours.
  • ORB daily engine (now archived in experiments/nifty_oracle.py) — a daily-bias model gating an opening-range breakout. A full-history backtest found no robust edge (see §11), so it was moved out of the live product. nifty_live.py stays only as a shared indicator/data utility.
The honest truth (repeated on purpose). Per-bar direction prediction on liquid index data is close to a coin toss (~50–53%). The edge is small and comes from selectivity — acting only on the strongest, best-timed setups (~54–59%) — combined with a 1.5 : 1 reward-to-risk ratio. There is no configuration, data source, or model that reaches 90%. Chasing that number is how retail traders lose money.

Design principles (the iron rules)

  1. No feature ships without a walk-forward backtest proving it helps. Plausibility is not evidence.
  2. Train/serve consistency. Every feature is computed identically in training and live — no lookahead, no data that only exists after the fact.
  3. Honesty over comfort. The UI shows the real hit-rate, labelled "not a guarantee." Losing signals are not hidden.
  4. Selectivity beats prediction. Sitting out (WAIT) is a first-class decision, not a failure.

4Feature engineering — the 13 indicators

The forecast models consume 13 features (BASE_COLS), all computed from 5-minute OHLC bars and all causal (only past/current data). This self-consistency is deliberate: every feature means the same thing in training and in live inference.

Why tree models don't need feature de-correlation. Several features overlap (EMA, MACD, RSI all encode momentum). Linear models would suffer from this multicollinearity; gradient-boosted trees simply pick the best split at each node and are unaffected. This is why no PCA / copula / whitening step is needed or used.

5The models — LightGBM & GradientBoosting

Ten trained models total. Both algorithms are gradient boosting — an ensemble of small decision trees where each new tree corrects the previous trees' errors. The difference is implementation, not idea.

LightGBMGradientBoosting (sklearn)
Used forForecast Window (8 models)ORB daily bias (2 models)
Data size~26,000 rows (big)~500 days (small)
WhyFast, handles large data, leaf-wise growthStable on small data, proven, less overfit-prone

5.1 Forecast models (8 × LightGBM)

For each index (BankNifty, Nifty50) and each horizon (5m / 15m / 30m / 60m) a separate binary classifier predicts P(price higher after k bars). Label: y = 1 if close(t+k) > close(t) else 0

LGBMClassifier(
    objective="binary", num_leaves=24, max_depth=4,
    learning_rate=0.02, n_estimators=500,
    subsample=0.75, colsample_bytree=0.7,
    reg_alpha=0.5, reg_lambda=2.0,      # strong regularisation
    min_child_samples=80)               # → resists overfitting noise

Training uses a held-out validation slice (last ~10% of sessions) with early stopping, then retrains on all data for production. Horizons in 5-min bars: 5m→1, 15m→3, 30m→6, 60m→12.

5.2 Daily-bias models (2 × GradientBoosting)

Predicts whether the day closes above its open. Features are daily: returns (1/3/5-day), RSI, EMA-20/50 distance, ATR%, range position, gap, day-of-week, plus (BankNifty only) MACD, Bollinger %b, Stochastic. Nifty50 stays lean — indicator features overfit it.

GradientBoostingClassifier(n_estimators=150, max_depth=3,
                           learning_rate=0.05, subsample=0.8)
FEATURE_SETS = {"BANKNIFTY": BASE+INDICATORS (13),
                "NIFTY50":   BASE (10)}

Candlestick patterns (doji, engulfing, hammer) are computed for the UI but are not model inputs — they did not improve accuracy.

6Confidence tiers — HIGH / MEDIUM / LOW

A raw probability like 0.53 is nearly meaningless on its own. Instead each forecast is bucketed into a tier whose real held-out hit-rate is measured and displayed. Thresholds are learned per horizon from the validation slice — not hard-coded — so the tiers actually fire.

TierDefinitionTypical held-out accuracy
HIGHTop ~28% most-confident calls (conf ≥ 72nd percentile)~53–57%
MEDIUMNext ~35%~49–53%
LOWRemaining ~37%~48–51% (coin toss)

Calibration (_calibrate_tiers) computes the confidence distribution on the validation set, sets the HIGH/MEDIUM cutoffs by percentile, and records each bucket's accuracy. Only the HIGH tier carries a usable edge; MEDIUM and LOW are shown for transparency but should not be traded alone.

Key insight. Accuracy does not come from predicting more — it comes from predicting less, but only when confident. The tier system is how the engine says "I don't know" most of the time and "I'm relatively sure" rarely.

7The STRONG signal — consensus + time filter

The ⭐ STRONG signal is the system's single actionable output. It is the result of two stacked filters, both derived from backtests.

Filter 1 — multi-horizon consensus

A single horizon at HIGH tier is ~54%. But when ≥3 of the 4 horizons are simultaneously HIGH and agree on direction, accuracy rises:

Horizons HIGH & agreeingBankNiftyMinutes
≥ 153.8%2445
≥ 255.9%1031
≥ 359.0%314
≥ 4 (all agree)60.4%67

The rule ships at STRONG_MIN_ALIGN = 3.

Honesty note (reconciled 30 Jul 2026). The table above is an early held-out validation cut, and the ≥4 row is only 67 minutes. On live logged sessions the STRONG signal comes in around ~54% (and the model's own stored strong_acc ≈ 54%). Treat ~54% as the honest, conservative STRONG number — the 59–60% here was a smaller, rosier sample. Also note: "N horizons agreeing on direction" (any tier) is a looser metric than "N horizons HIGH and agreeing", so it reads a few points lower again. Different cuts, all honest — but ~54% is the one to quote.

Filter 2 — the midday dead-zone

Backtesting the 30-minute HIGH tier by time of day revealed a consistent pattern across both indices:

WindowBankNiftyNifty50
Morning 09:15–11:0055.1%56.8%
Midday 11:00–13:3047.9%52.6%
Afternoon 13:30–15:3054.7%55.3%

Midday is the model's weakest window — BankNifty actually drops below a coin toss. Therefore STRONG is suppressed between 11:00 and 13:30 (DEAD_ZONE). During those hours the UI shows a distinct "WAIT — midday dead-zone" banner even when the horizons agree.

strong = (align >= 3) AND (time not in 11:00–13:30)
signal = {strong, dir, align, acc, window}   # window: "prime" | "midday"
Net effect. Out of ~375 forecast minutes per session, STRONG fires only a handful of times — precisely when several models agree with high confidence in the reliable hours. Every other minute is an honest WAIT.

8The ORB daily engine

The Opening-Range Breakout engine (nifty_live.py) is the project's original trading strategy, separate from the minute-by-minute forecaster. It was long described as the "money engine" — but an honest full-history backtest (§11) does not support that. It is documented here as designed; the honest performance verdict is in §11.

The rules

  1. Bias at the open. The daily model sets a LONG/SHORT bias with a probability. If confidence < 58%, the whole day is NO-TRADE (unless the BankNifty adaptive unlock triggers).
  2. 09:15–09:45 build the opening range (its high and low). No trading.
  3. Entry: a 1-minute close beyond the range in the bias direction.
  4. Stop: the opposite side of the range. Target: 1.5R.
  5. Exits: stop, target, or the 15:15 square-off — whichever first.
  6. Limits: BankNifty up to 5 trades, entries until 14:30; Nifty50 up to 3, entries until 13:30. (Both tuned by backtest — extending Nifty50 loses.)

Adaptive unlock (BankNifty only)

On borderline-confidence days, a breakout is taken only if 4 of 4 intraday indicators (RSI, EMA, MACD, VWAP) align with it; otherwise the day is skipped. (Only these four count — a July 2026 fix stopped the expanded 7-chip market-state card from loosening this gate to "4 of 7.")

Honest verdict (supersedes the old "money engine" claim). On the full 17-month / 351-session walk-forward, even with the adaptive unlock and all tuned settings, the ORB engine has no robust edge: BankNifty −12.6R, Nifty50 +0.9R (flat), and both LOSE on the training half while only profiting on the recent test half — regime luck, not an edge. Win-rate ~44–49% at 1.5:1 is break-even before costs and negative after. Do not trade this with real money. See §11.

ORB trading backtest — the honest verdict

The ORB strategy was run over the full 17-month / 351-session dataset (walk-forward daily bias), including the tuned per-index settings and BankNifty's adaptive unlock. Results, split into a training half (first 60%) and a test half (last 40%):

IndexTrain (first 60%)Test (last 40%)Full 351
BankNifty−15.2R (43% win)+2.6R (53%)−12.6R

No robust edge. Both indices lose on the training half and only profit on the recent test half — the signature of regime luck, not a real edge (a genuine edge is positive on both). A parameter sweep found no setting positive on both halves. Win-rate ~44–49% at 1.5 : 1 is break-even before costs; realistic ~0.15R/trade transaction costs push it negative. The old "positive-R money engine" claim came from a short, lucky 60-day window. Conclusion: do not trade this with real money — use it as an information and paper-trading tool.

14Daily operating guide

  1. Any time (optional): pre-train models — python3 train_models.py.
  2. At/after 09:15 on a weekday: python3 nifty_dashboard.py. Angel logs in automatically; the browser opens to localhost:8181.
  3. Open /forecasts. Watch the banner:
    • ⭐ STRONG BUY/SELL → the actionable moment (act on your own judgement + risk rules).
    • WAIT → do nothing. This is most of the day, by design.
    • WAIT — midday dead-zone → models agree but it is the weak 11:00–13:30 window.
  4. Cross-check with the Beast (/): consensus, indicator chips, paper P&L, AI Co-pilot.
  5. Respect position sizing (1% risk), the 15:15 square-off, and NO-TRADE days.
  6. Any time, verify honesty: python3 backtest.py.

15Risk management & limitations

Hard limits of this system

  • Accuracy ceiling ~59%. No amount of tuning reaches 70–90%. Index direction is genuinely near-random at short horizons.
  • Warm-up. Forecasts need ~1.5 hours of candles before the rolling indicators (20-bar windows) are valid.
  • Free-data quirks. Yahoo lags; Angel revises the final bar to the official close (a live tick and the official close can differ slightly).
  • Regime dependence. Trained on Feb 2025–Jul 2026. A market regime very unlike that period will degrade accuracy until retrained.

Survival rules

  1. Risk 1% of capital per trade. Never raise it. A 4–6 loss streak is normal; at 10% risk that is account death.
  2. Winners target 1.5R, losers cut at 1R — the math, not the hit-rate, is the edge.
  3. Only act on STRONG, in the good hours. WAIT is a decision.
  4. Paper-trade ≥ 20 sessions before real money. Only risk what you can lose entirely.
  5. Nothing here is financial advice. Forecasting is probabilistic.

16Statistical methods — what we kept & removed

Beyond the classic indicators, the project experimented with heavier statistical / econometric methods. True to the iron rule, each was tested, not assumed. Some survived and are live features; the more sophisticated ones did not and were removed. This section documents both.

16.1 Kept — statistical features that survived testing

These are among the 13 live features. They stayed because they are computed identically in training and live (no skew) and earned their place in the walk-forward backtest.

MethodWhat it measuresHow it's computed
Hurst exponent Whether the market is trending (H>0.5), mean-reverting / choppy (H<0.5), or a random walk (H≈0.5). The model behaves differently in each regime. Rescaled-range (R/S) analysis over a rolling 20-bar window: log(R/S)/log(20).
Parkinson volatility Intraday volatility using the high–low range — more efficient than close-to-close because it uses the full bar. √(mean(ln(H/L)²) / (4·ln2)) over 12 bars.
Regime volatility How wild the market is right now — a simple statistical "temperature." Rolling standard deviation of 1-bar returns (20 bars).

16.2 Removed — sophisticated statistics that failed the test

These sounded powerful and dominated the old engine's feature-importance list (it once claimed "statistical features are the top 6"). But an honest walk-forward exposed two fatal problems: a train/serve mismatch (they were built from 2 years of continuous history at training time, but only today's intraday bars at live time — so they meant different things) and no reliable accuracy gain.

MethodThe ideaWhy it was removed
GARCH(1,1) An econometric model that forecasts volatility on the principle that volatility clusters — calm follows calm, turbulence follows turbulence. Train/serve skew (rolling fit needs long history, absent intraday); slow; no measurable edge.
Cointegration spread z-score Measures how far BankNifty and Nifty have drifted from their usual relationship — a pairs-trading / mean-reversion signal. The normalisation referenced the series' start, which differed wildly between the 2-year train window and a single live day; did not help direction.
India VIX features The market's "fear index" (raw level + rolling percentile) as a sentiment input. Helped inconsistently across horizons; part of the skewed "extras" set. Note: VIX data is still cached, just not fed to the model.
The lesson. Sophistication is not edge. GARCH and cointegration are genuine, respected techniques — and they still failed here, because a method only earns a place if it survives an honest, train/serve-consistent backtest. The plain statistical features that stayed (Hurst, Parkinson, regime volatility) won precisely because they are simple and consistent, not because they are fancy.
