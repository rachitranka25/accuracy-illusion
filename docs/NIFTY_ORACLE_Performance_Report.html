3ML Models — Under the Hood

3.1 Why LightGBM

The system uses Microsoft LightGBM — a gradient boosting framework that builds an ensemble of small decision trees where each new tree corrects the previous trees' errors. It was chosen for specific, defensible reasons:

Speed on 26K rows~2s train~5s~3s~30s+
Leaf growth strategyLeaf-wise (best-first)Level-wiseLevel-wiseN/A

Tabular data SOTAYesComparableLowerGenerally worse
Correlated featuresNatural (tree splits)NaturalNaturalNeeds PCA

3.2 Hyperparameter configuration

LGBMClassifier(
    objective     = "binary",
    num_leaves    = 24,          # shallow trees — resist overfitting noise
    max_depth     = 4,           # hard depth cap
    learning_rate = 0.02,        # slow learning → stability
    n_estimators  = 500,         # with early stopping at 50
    subsample     = 0.75,        # row sampling (stochastic)
    colsample_bytree = 0.7,     # feature sampling per tree
    reg_alpha     = 0.5,         # L1 regularisation
    reg_lambda    = 2.0,         # L2 regularisation (strong)
    min_child_samples = 80       # large minimum leaf size
)
Design rationale. In a domain where signal-to-noise is ~0.02 (barely above random), aggressive tree growth = memorising noise. These settings — num_leaves=24, max_depth=4, min_child_samples=80, heavy L1/L2 regularisation — force the model to find only the most robust splits.

3.4 Training methodology: walk-forward validation

Timeline: ─────────────────────────────────────────────────────► Phase 1: │◄──── Train (first ~90% ≈ 306 sessions) ────►│◄── Val (~10% ≈ 45 sessions) ──►│ │ Learn tree splits from historical data │ Calibrate HIGH/MED/LOW tiers │ Phase 2: Measure honest out-of-sample accuracy per horizon, per tier, per time-of-day Phase 3: Retrain on ALL data for production, deploy with validation-calibrated tier thresholds
The iron rule: train/serve consistency. Every feature is computed identically in training and live. No lookahead, no data that only exists after the fact. This rule was responsible for removing several sophisticated features (GARCH, VIX, cointegration) that looked good in training but degraded in live — the classic train/serve mismatch.

Why no PCA / feature decorrelation? Several features overlap (EMA, MACD, RSI all encode momentum). Linear models would suffer from multicollinearity. Gradient-boosted trees simply pick the best split at each node — they naturally select the most informative feature and are unaffected.

5Confidence Tiers & the STRONG Signal

5.1 Tier calibration

Raw probability outputs (e.g. 0.53) are nearly meaningless. The system buckets every forecast into a calibrated confidence tier whose real held-out hit-rate is measured and displayed.

TierDefinitionBacktested OOS accuracy
HIGHTop ~28% most-confident calls (conf ≥ 72nd percentile)~53–57%
MEDIUMNext ~35%~49–53%
LOWRemaining ~37%~48–51% (coin toss)

5.2 The STRONG signal

STRONG = (≥3 of 4 horizons are HIGH tier AND agree on direction)
          AND
         (current time NOT in 11:00–13:30 dead-zone)

Why the dead-zone? Backtesting the 30m HIGH tier by time of day:

WindowBankNiftyNifty50
Morning 09:15–11:0055.1%56.8%
Midday 11:00–13:3047.9% (below coin toss)52.6%
Afternoon 13:30–15:3054.7%55.3%
Net effect. Out of ~375 forecast minutes per session, STRONG fires only a handful of times — precisely when several models agree with high confidence in the reliable hours. Every other minute is an honest WAIT.

10Honest Conclusions

  1. The ~50% direction ceiling is real and well-tested. It's a property of liquid index markets at short horizons, not a data or model limitation.
  2. The edge is in selectivity, not prediction. Going from "predict everything" (~50%) to "only act on STRONG in good hours" lifts NIFTY50 to ~58–66%.
  3. Day-to-day variance dominates. The same model produces 84.5% on a trending day and 12.3% on a choppy day. This is not a bug — it's the nature of direction forecasting.
  4. NIFTY50 > BANKNIFTY for predictability — consistently, across all timeframes and signal types. Deeper institutional participation creates more persistent trends.
  5. Accuracy ≠ Profit. A cost-aware selective backtest (STRONG + prime window + adaptive stops + slippage) lost money on both indices on 28 Jul. A typical 30-min move (~36 / ~14 pts) barely exceeds round-trip cost + slippage. Chase expectancy, not accuracy.
  6. The honest STRONG number: ~54–59%. The 60%+ on good days is real but regime-dependent; the average converges to ~54–59% — still above random, but not a money machine.
The one-line takeaway. This system is built on radical honesty: the accuracy is measured and displayed honestly, losing signals are not hidden, and the design principles (walk-forward validation, train/serve consistency, no-ship-without-backtest) are enforced as iron rules. The small, real edge lives in disciplined selectivity — predicting less, but only when confident.
