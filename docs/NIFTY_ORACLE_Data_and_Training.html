How much data, and what more would do

Exactly how much data Nifty Oracle trains on today, and an honest, tested answer to “would more data make it more accurate?”

Why 5-minute for one and daily for the other. The forecaster predicts the next few minutes, so it needs fine-grained 5-minute bars — 26,000 of them give it plenty of examples. The daily engine predicts the whole day's direction, so one data point per day is enough; 2 years = ~494 days is a healthy sample for a once-a-day decision.

2How the data is actually used

Raw rows are not fed in blindly. Each model goes through a disciplined, no-lookahead pipeline:

  1. Features: each 5-minute bar becomes 13 numbers (RSI, EMA distance, MACD, Bollinger, ATR, VWAP, Hurst, time-of-day, …) — all causal (past/present only).
  2. Train / validation split: the last ~10% of sessions are held out as a validation slice. The model trains on the earlier part, and its confidence tiers (HIGH / MEDIUM / LOW) are calibrated on the held-out part — never on data it trained on.
  3. Walk-forward test: to measure honest accuracy, the last 45 sessions are held out entirely; the model only ever trains on the past and is tested on the future.
  4. Production retrain: once validated, the model retrains on all data for live use.

This is why the accuracy numbers are trustworthy: nothing is scored on data it has already seen.

3The experiment: does more data help?

We trained the 30-minute model (the most actionable horizon) on increasing amounts of history — 3, 6, 9, 12, 15 months — and tested each on the same fixed 45-session hold-out. If accuracy keeps climbing, more data helps. If it flattens, it doesn't.

4Reading the result honestly

Three things the numbers tell us:

  1. Raw accuracy has a ~50% ceiling that data cannot move. At 3 months or 15 months, the plain accuracy is ~50%. The limit is set by the problem — short-horizon index direction is close to random — not by how much history we feed.
  2. The curve is noisy, not a steady climb. HIGH% bounces (48 → 49 → 49 → 50, and Nifty50 even dips to 47 at 12 months) before the full-data reading. A real "more-data-helps" signal would rise smoothly; this doesn't.
  3. Full data (≈17 months) gives the best calibration. Both indices read best at the largest size — which is exactly what the live system already uses. We are sitting at the useful amount, not short of it.
The hidden danger of “just add years of data.” Older data (2–4 years back) comes from different market regimes — different volatility, different behaviour. Training on it can hurt, because the model learns patterns that no longer apply. More data is only better when it is relevant data.

5What actually improves accuracy

Since raw accuracy is capped, gains come from using the model more wisely, not from feeding it more:

LeverEffectStatus
More training data (older history)~none; risks stale-regime noiseNot worth it
Regular retraining (keep data current)Keeps the model matched to today's regimeDo this — train_models.py
Selectivity — act only on HIGH-tier + consensus~50% → ~54–59%Shipped (STRONG signal)
Time filter — skip the midday dead-zoneRemoves the model's worst hours (~48%)Shipped
Risk:reward (1.5R targets)Makes ~55% profitable over timeIn the ORB engine
The one-line takeaway. We use ~17 months / 26,265 bars — the right amount. More history won't lift accuracy (the ceiling is the market, not the data). Keep the data fresh by retraining, and squeeze accuracy through selectivity (STRONG signal, time filter), not volume. Every test in this project points the same way: the edge is discipline, not a bigger dataset.
